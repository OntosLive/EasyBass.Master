# EasyBassMaster · Фойе на исходном HTML главной · R5

**11 октября 2026. Статус: предложение в черновом PR №32, не утверждённый релиз.**

## Причина изменения

После семи последовательных проектных разговоров пользователь указал на принципиальное расхождение R3/R4: «фойе должно быть на основе шаблона ... первой страницы, но с содержанием другим». Принятая главная — самостоятельная авторская HTML-композиция «Пространство, в котором можно найти свой». В R3 от неё брали только первый CSS-блок и вручную собирали новую страницу, визуально похожую на комнату. **Общие CSS-классы не являются общим HTML-шаблоном.**

### Инвариант

**Единственный источник художественной структуры запросных фойе: \`design/visual-home/index.html\`.** Публичные N.0 имеют индивидуальное содержимое, но используют исходные компоненты, структуру, CSS и JavaScript комнаты. Не создавать независимое дерево \`topbar/hero/cards\` и не возвращать газетную оболочку. Широкий и мобильный экран являются версиями одной и той же сцены.

Комната \`/\` остаётся побайтно утверждённой и не меняется. Никакой отдельной обязательной страницы \`/foyer/\`: поисковое N.0 само является фойе; оттуда можно **немедленно позвонить** или **непосредственно войти в \`/\`**. «Придворный» — функция ответа на запрос, не чат-бот и не нарисованный персонаж.

## Реализация R5 в черновой ветке

- \`scripts/room_template_foyer.py\`: парсит реальный HTML главной, использует его исходный DOM, создаёт отдельный экземпляр страницы на каждый N.0, меняет данные в проверенных слотах. Исходная комната не перезаписывается.
- \`scripts/courtier_foyer.py\`: совместимый импорт без самостоятельного генератора разметки.
- \`scripts/dual_view.py\`: передаёт **фактический HTML комнаты** в генератор, а проверка выпуска требует идентичности структурных узлов, шапки, меню, галереи, света, контакта и прямого действия.
- \`tests/test_courtier_foyer.py\`: сравнение DOM-разделов и обоих исходных \`<style>\` блоков с оригиналом, сохранение JS, 4+4, авторских заголовков/модуляций/canonical, отсутствия газетных CSS.
- \`scripts/courtier_smoke.py\`, \`scripts/visual_presentation_smoke.py\`: браузерная проверка ширин, компоновки, прямых выходов, иллюстраций и текстового эталона.

**Отличающиеся данные по N.0:** индивидуальные H1, текст авторской модуляции, исходный kicker, SEO title/description/canonical, актуальное место тематического SVG для ремонтных запросов, конкретные маршруты 4 диапазонов/4 сведений мастерской/2 авторских выхода. Ни один ответ не сочиняется Python.

**Общая база:** остальные разделы, галерея и художественная фотографическая комната пока унаследованы от главной. Это намеренный предел именно *структурного* R5: нижний текст не переписан автоматически на 795 разных историй. Не выдавать это за завершённую авторскую адаптацию **всех** секций для каждого вопроса.

## Что нельзя потерять

- Одна реальная мастерская/коллекция/клуб. Одна авторская комната. Конверсия — встреча, сделка не навязывается.
- Индивидуальная речь каждого из 795 N.0: заявленное знание и фактическая возможность должны согласовываться.
- Ровно 825 канонических визуальных HTML + 825 технических \`/text/\` с \`noindex\`. Текстовая версия не является художественным шаблоном.
- N.1 остаётся независимым предметным исследованием, не превращается в торговое фойе.
- Существующие канонические адреса, контакты, sitemap, 4+4 и прямой выход. Никаких обещаний отсутствующих инструментов, фотографий ремонта, цен и сроков.
- Не смешивать факт публикации, автоматические тесты и художественное утверждение владельца.

## Приёмка и продолжение

1. Полный CI собирает 795 N.0 на исходном HTML комнаты и сохраняет 825/825 без дублей URL и битых ссылок; мобильные тесты, переключение света и галерея.
2. Открыть **сам HTML** нескольких предметно разных запросов (выбор, ремонт, аренда) и первую комнату рядом; проверить целостность ансамбля и телефон/дверь.
3. Затем провести содержательный редакционный проход по областям нижних секций: что одинаково у всех фойе по праву принадлежности к одной мастерской, а что должно получить **индивидуальное** смысловое наполнение из существующих авторских данных. Это следующий *содержательный* этап, не предмет механического создания 795 копий.
4. До художественной приёмки PR №32 остаётся draft, \`main\` и публичная комната неизменны. Не выдавать черновую реализацию за новый принятый канон.

**Короткое различение:** R3 копировал стили. R5 клонирует исходный HTML комнаты. Следующий слой — индивидуальная режиссура содержания внутри наследуемой формы.
