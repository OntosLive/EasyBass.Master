## Существующая сцена
EasyBassMaster — частная Мастерская контрабаса: работающие мастера, коллекция, история инструментов и возможность знакомства. Главная — самостоятельный вход в это пространство. Она не должна превращаться в список SEO-запросов, складской отчёт или бухгалтерию. Три пространства «Коллекция», «Мастерская», «Знакомство» самостоятельны. Предметные публикации живут в «Подшивке».

## Генеративное ядро
Реальная способность мастерской → возможная человеческая ситуация → поисковая гипотеза → восстановленная человеческая реплика → редакционное различение → постоянный адрес → публикация → измеренный отклик → уточнение способности.

Частотность — дополнительный сенсор, а не автор. Нулевая частотность сама по себе не запрещает страницу. Сначала проверяется реальность возможности, смысл сцены и честность предложения.

## Два самостоятельных публичных документа
N.0 — короткий поисковый вход, отвечает на конкретное действие: купить, арендовать, продать, оценить, восстановить. Достаточно названия, одного узнаваемого различения, контакта и перехода.
N.1 — самостоятельное знание: как устроен предмет или ситуация, что действительно изменяет выбор или результат. Сохраняется в /details/<slug>/.
Оба документа могут индексироваться при разных поисковых намерениях и самостоятельных текстах; у каждого свой self-canonical, оба включаются в sitemap. Никакого автоматического запрета N.1. Разные заголовки без разного смысла недостаточны.
Страница N.0 никогда не является укороченным пересказом N.1.
План тем не означает обязательные две страницы для каждого синонима: пары создаются только там, где обе функции действительно существуют.

## Паспорт сцены перед написанием
1. Внутреннее имя темы и родитель.
2. Возможная поисковая формулировка (гипотеза/данные).
3. Человеческая реплика, восстановленная из запроса.
4. Кто этот человек, что уже происходит.
5. Одна неопределённость или напряжение.
6. Предполагаемая им форма решения.
7. Предметное различение — что изменится в его практике.
8. Реальная способность мастерской и её подтверждение.
9. Что останется уточнить при личном контакте.
10. N.0 search_title и N.1 editorial_title (разные).
11. Связи родителя, детей, соседей и источники.
12. Статус фактов: подтверждено / гипотеза / требует проверки.

Один текст: один человек, одно напряжение, одно различение, одна естественная дверь. Не писать с позиции «клиенты часто ищут». Продолжать мысль человека. Не объяснять ему устройство нашего SEO, фонда или коммерческой архитектуры.

## Морфология контрабаса
Режим отношений: приобретение / аренда / выкуп у владельца / оценка / настройка / реставрация / обмен / подбор / проба.
Предмет: конкретный инструмент / мастерская традиция / мануфактура / старинный / современный / размер / конструкция / состояние / история / принадлежности.
Музыкант: начинающий / ученик / студент / оркестрант / солист / джазовый исполнитель / педагог / владелец.
Сцена: обучение / поступление / концерт / гастроли / замена во время ремонта / переход на инструмент иного класса / поиск своего звука.
Критерий: геометрия, мензура, техника, смычковый ответ, тембр, удобство, состояние, документированное происхождение.
География и сроки являются дополнительными координатами, а не автоматическим множителем URL.
Запрещено механическое декартово произведение всех осей.

## Подлинность и осторожность
Существование предметной страницы не означает наличие экземпляра, проверенную атрибуцию, цену, срок исполнения или готовность к сделке. Нельзя называть всякий московский контрабас инструментом московского изготовления.
Продажа и аренда — независимые маршруты. Прошедшие арендные платежи не засчитываются в цену выкупа в текущей модели мастерской.
Точные свойства, происхождение, состояние, история и изготовитель проверяются по конкретному экземпляру и источникам.
Внутренние остатки, финансовые мотивы, число реставрационных активов, целевая экономика фонда и механика генерации не публикуются.

## Два прохода
Проход 1: собрать и дедуплицировать предметную карту с устойчивыми slug, родителями, паспортами и маршрутами; обойти уже опубликованные страницы и исторические URL.
Проход 2: для каждой темы написать собственный текст, подтвердить факты и перечитать соседние темы. Текст, переносимый на соседний запрос заменой двух слов, отбраковывается.
Сначала строим гипотезы. Измерение Wordstat, подсказки, открытые объявления, профессиональные форумы, Webmaster и реальные обращения помечаем по происхождению. Никогда не выдавать придуманные запросы за частотность.

## Компилятор и проверки (проект переноса)
Источник истины — структурированные данные, а не сотни ручных копий HTML. От ONTOS.RENT берем идеи inventory → links audit → site build → tests → validation → GitHub Pages.
Для EasyBassMaster сначала отдельный простой статический генератор с едиными шаблонами, CSS, контактным блоком, метаданными и sitemap. Не копировать 1980 тем, Payload, Docker или старые ветки.
Проверки: схемы, уникальность темы и slug, человеческие заголовки, реальные ссылки и родители, отсутствие самоссылок и дублей, существование страницы, правильный relative CSS, responsive layout, контакт +7 (909) 694-55-44, canonicals, sitemap, исключение внутренних документов. Боковые мосты добавляются только как следующее полезное различение.
Сохранить существующие адреса и газетные выпуски; не ломать главную, «Коллекцию», «Мастерскую», «Знакомство».

## Выпускная дисциплина
Одна рабочая волна ориентировочно 50–60 независимых тем (не квота); если обоснованных меньше — выпускать меньше. Сначала паспорт и реестр, потом редактура, проверки и только затем публикация. Наличие коммита, успешная сборка и живой публичный сайт — разные состояния. Не объявлять релиз завершённым без подтверждённой публикации.
