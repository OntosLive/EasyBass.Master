# EasyBassMaster · комната и прихожая / визуальный канон R1

**Режиссура:** посетитель приходит с конкретным запросом на одну из существующих страниц; каждая такая страница узнаёт запрос, даёт короткий предметный ответ и открывает прямую дверь в главную. **Главная является комнатой**: утверждённая композиция `EasyBassMaster_Concept_Home.html`, превращённая в рабочий `/index.html`.

## Две предыдущие неизменяемые фиксации

1. **`aacc9d37e29392d004d9ede3d7c914dd0d496ca6`**, ветка `codex/room-home-canon-20261011`: первый фикс понравившегося HTML, **без изменения визуальных блоков**. 13 повторённых внутри HTML изображений заменены относительными ссылками на три байт-в-байт идентичных WebP, чтобы не хранить 3,2 МБ повторяющегося base64.
2. **`53230740a040d0e97a4a0e8a0d79f68067b15364`**: отдельно заменено только одно слово: «Поводов вернуться: звук, **работа**, разговор» → «...звук, **творчество**, разговор». Другие употребления «работа» сохранены до самостоятельного редакционного решения.

Проверка исходного файла: SHA-256 `298d9cd06b3f6bcfd1ff5d0db738b5414560014c48dc7605076016ac783e4176`. Прототип сохранён в `design/room/index.html`; `design` исключён из Jekyll. Существующую ветку `main` **не меняем** до просмотра и согласования.

## Архитектура интеграции: третья ветка

**`codex/room-foyer-integration-20261011`** начинается строго от второго коммита. На ней:

- `/index.html` буквально получает композицию утверждённой страницы: тот же hero, фото, заголовок, атмосферный переключатель JavaScript, галерея и все визуальные разделы. Для реальной сборки используются три отдельных WebP; подтверждённые телефон / Telegram / WhatsApp / неактивный MAX встроены в прежнюю контактную секцию через существующий `.contact-block`, чтобы вся поисковая сеть наследовала одни контакты.
- Все прежние N.0, N.1, модели, институциональные страницы, подшивка и старые выпуски **сохраняют адрес и содержание**. `scripts/foyer_wrap.py` после исходной сборки формирует на каждой странице одну малую фотографическую дверь с ссылкой на `/` и подключает `assets/visual/foyer.css`.
- На N.0 исходное движение сохраняется: **H1 запроса → индивидуальная короткая фраза → проверенный контакт → дверь → прежние 4+4 маршрута**. Прямой выход в мастерскую доброволен: посетитель всё ещё может позвонить или перейти в глубокую статью без лишней обязательной страницы.
- На глубоких статьях приглашение следует **после знания** и до контакта. Ни одно доказательство / ссылка на документ не теряется.
- **Новый индексируемый «коридорный» URL не создаётся.** Существующие страницы и есть прихожие. Иначе мы создали бы SEO-дубли и вынужденную пересадку посетителя по лишней ссылке.

## Принципы

- Комната главной страницы сохраняет одобренный дизайн. Вся разница только в подключении настоящих файлов и официального контакта.
- Система представления меняется отдельно от смысловой и поисковой машины. 825 существовавших адресов и sitemap проходят проверку после реальной Jekyll/Python-сборки.
- Боковые сервисы и чужие платформы не нужны: сайт по-прежнему чистый статический HTML/CSS/JavaScript, выдаваемый GitHub Pages. Мобильный режим обязателен.
- Обработанные фотографии являются художественным видением реальной коллекции, а не строгим свидетельством фактической нынешней обстановки комнаты.
- PR даёт **скачиваемую сборку**, не деплоит новый дизайн; на `easybassmaster.ru` ничего не меняется до merge, одобряемого владельцем.

## Важное исключение для компилятора

`scripts/site_core.py` читает текущий подтверждённый контакт из `index.html`. Поэтому при переносе визуального HTML обязательны ровно один `.contact-block`, реальный телефон `+7 909 694-55-44`, проверенные ссылки Telegram и WhatsApp и некликабельный символ MAX. Этот контракт не заменяется выдуманными реквизитами из иллюстративных макетов.
