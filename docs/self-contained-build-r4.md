# EasyBassMaster · R4: самодостаточная сборка утверждённой комнаты

**Статус:** техническая ветка на базе R3. Содержание, композиция, маршруты и пользовательский интерфейс НЕ изменяются.

## Обнаруженный скрытый разрыв

До R4 опубликованный дизайн технически собирался из `main`, **но исходный HTML комнаты, три WebP, оформление отдельной прихожей и генератор визуальных дверей забирались во время CI из изменяемой ветки** `codex/room-foyer-integration-20261011` через `git fetch`/ `git show FETCH_HEAD`. Таким образом, одни и те же исходники `main` могли завтра дать иной результат, а удаление экспериментальной ветки останавливало бы публикацию.

Это нарушало сформулированный для мастерской принцип внешнего канона: результат должен быть воспроизводим из зафиксированного состояния Git, а не зависеть от другой живой сцены.

## Что изменено в R4

В **том же репозитории** сохранены без повторной обработки и без новой вёрстки:

- `design/visual-home/index.html` — утверждённая HTML-комната из уже использовавшегося snapshot-коммита; в том числе отдельная правка слова «творчество», галерея, переключение света, настоящий контакт;
- `design/foyer/index.html` — экспериментальная самостоятельная прихожая для собственного просмотра, без введения третьего обязательного шага;
- `assets/photography/{room-golden,room-evening,row-amber}.webp` — три бинарно идентичных изображения; каждый файл меньше 210 КБ;
- `assets/visual/foyer.css` и `scripts/foyer_wrap.py` — именно те исходники, которые уже использовались на работающей визуальной версии.

В `scripts/dual_view.py` функция `design(...)` теперь читает источник **непосредственно из данного checkout**. `.github/workflows/jekyll-gh-pages.yml` больше не загружает другой ref и запускает `compose` без `--design-ref FETCH_HEAD`.

Папка `design` добавлена в `_config.yml` как исключаемая из публичного Jekyll-вывода. Поэтому её наличие не создаёт второй index или лишние адреса.

## Контракты, которые продолжают действовать

- **Две версии по 825 документов:** индексируемая визуальная версия на обычных адресах и техническая `/text/` с `noindex`, общий единственный корпус авторского текста.
- **795 N.0-фойе**, каждое отвечает на собственный вопрос, содержит телефон и дверь непосредственно в утверждённую комнату, 4+4 реальных маршрута; без обязательного третьего экрана.
- N.1 остаются самостоятельным знанием, `/foyer/` — самостоятельная неиндексируемая сцена.
- Телефон `+7 (909) 694-55-44`, Telegram, WhatsApp, некликабельный MAX, sitemap, canonical и старые маршруты остаются такими, какими их уже утвердили.
- `assets/visual/room-parent.css` по-прежнему **извлекается автоматически из первого CSS-блока утверждённой комнаты**, чтобы все фойе наследовали визуальную форму оригинала.

## Как вносить изменения дальше

Теперь изменение фотографий, композиции комнаты и её унаследованного стиля производится **отдельным осмысленным коммитом**, с актуализацией Git-blob-контракта в `tests/test_bundled_visual_sources.py`; потом полные тесты Jekyll → N.0/N.1 → dual_view → Chrome и визуальная приёмка.

Исходник можно найти без поиска других веток. Это **не новая версия дизайна**, а перевод уже признанного результата в устойчивую и воспроизводимую инфраструктуру.

**Важное:** не смешивать внедрение R4 с черновой [Архитектурой знакомства R1](https://github.com/OntosLive/EasyBass.Master/pull/29), которая ещё ожидает реальных предметных свидетельств. R4 не придумывает номера контрабасов, фотографии ремонтов, наличие или звук.
